# 문항 검수 흐름

문항이 쓰이기까지의 절차와, 무엇을 CI가 보고 무엇을 사람이 보는지 정리한다.

## 상태 전이

```
작성(self / synthetic) → pending → approved
                              └──→ rejected
```

- `pending`: 초안. 학습자에게 보여 주지 않는다.
- `approved`: 검수자가 정답, 해설, 난이도를 확인한 문항.
- `rejected`: 쓰지 않는다. 이유는 PR이나 커밋 메시지에 남긴다.

## approved로 바꿀 때 기록

```yaml
review: {status: approved, by: kky, date: "2026-11-04"}
```

- `by`(검수자)는 필수다. 없으면 CI가 실패한다.
- `date`는 따옴표로 감싼 `YYYY-MM-DD`로 적는다.
- `source: synthetic` 문항은 반드시 approved를 거친 뒤에만 사용한다.

## 확인 담당

| 확인 항목 | CI(자동) | 사람 |
|---|---|---|
| YAML 문법, 스키마(필드·타입) | O | |
| 문항 id 중복, 파일명과 노드 id 일치 | O | |
| 정답이 보기 안에 있는지 | O | |
| approved인데 검수자가 없는지 | O | |
| 해설 길이·줄 수 (경고만) | O | |
| 정답이 실제로 맞는지, 오답 보기가 오답인지 | | O |
| 해설의 정확성과 문체 | | O |
| 노드에 맞는 문항인지, 난이도 적절성 | | O |
| 회사 자료·시판 교재 문항이 섞이지 않았는지 | | O |

## 편집 후 머지 순서

1. 브랜치에서 수정하고 PR을 만든다.
2. `graph-validate`와 `CI`가 초록불인지 확인한다.
3. 검수자가 위 사람 확인 항목을 보고 머지한다.
